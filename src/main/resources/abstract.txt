Microservice architectures built on Java frameworks such as Spring Boot are increasingly targeted by attackers who exploit inter-service trust once perimeter defences are bypassed. Existing security research in this domain has focused predominantly on prevention-oriented mechanisms such as mutual TLS, OAuth 2.0, and zero-trust access control, leaving a gap in detecting attackers who have already gained a foothold within the system post-compromise. This paper proposes a post-compromise attack detection framework that injects honeytokens—decoy API keys, JWT claims, database records, and internal endpoints—directly at the API gateway layer of a Java microservice ecosystem. Because these tokens serve no legitimate function, any interaction with them provides a high-confidence indicator of malicious activity occurring after initial compromise, including reconnaissance, stolen-credential replay, and lateral movement. The proposed system, implemented using Spring Cloud Gateway and Redis for low-latency honeytoken lookup, integrates a filter chain that monitors requests in real time and triggers alerts upon honeytoken access, without disrupting legitimate traffic. We evaluate the framework in a simulated multi-service environment against common post-compromise attack patterns, including token replay and endpoint enumeration, measuring detection rate, false positive rate, detection latency, and system overhead. Experimental results demonstrate that the proposed gateway-injected honeytoken approach achieves high detection accuracy with negligible false positives and minimal added latency, offering a lightweight complement to existing prevention-based security mechanisms in Java microservice deployments by extending protection beyond the point of initial breach.
